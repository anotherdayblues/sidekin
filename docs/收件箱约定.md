# 收件箱约定

**结论：** 制作端把东西交给随伴，只走一条路：往收件箱放一个文件夹，再读随伴写的回执。制作端指 Codex 里的 Skill，以后也可以是别的工具。两边只依赖这份约定，不依赖对方的内部结构。

## 收件箱在哪

收件箱是随伴数据目录里的 `inbox/` 文件夹：

| 系统 | 位置 |
| --- | --- |
| macOS | `~/Library/Application Support/app.suiby.desktop/inbox/` |
| Windows | `%APPDATA%\app.suiby.desktop\inbox\` |
| Linux | `~/.local/share/app.suiby.desktop/inbox/` |

设置环境变量 `PET_STUDIO_DATA` 可以换成别的数据目录，测试时用。

## 怎么放

1. 先写到 `inbox/.tmp-<名字>/`。以点开头的文件夹，随伴不会去读。
2. 文件全部写完后，把它改名为 `inbox/<名字>/`。改名是一步完成的，随伴不会读到写了一半的包。
3. `<名字>` 只用字母、数字、`-` 和 `_`，并且每次都不一样。现在的做法是宠物编号加毫秒时间。

## 随伴认得的包

随伴按文件夹里的说明文件判断是什么：

| 说明文件 | 是什么 | 随伴怎么做 |
| --- | --- | --- |
| `pet.json` | 宠物包，旁边放图集（可附 `outfits/` 与 `activities/`） | 检查后导入。编号已存在时更新原来那只。选中它，弹出主窗口，宠物落进展示窗 |
| `teaching.json` | 新本领，旁边放 `actions/` | 检查后变成草稿，弹出主窗口，读卡口送出草稿卡 |
| `outfit.json` | 增量换装包，旁边放 `outfits/<id>.webp`（可选 `activities/`） | 校验尺寸与目标宠物一致后增量写入衣柜与排程，**完全保留**原图集、`sleepStrip`、`custom/` 与其他服装；选中该宠物并刷新主窗口与桌宠 |

上述说明文件都没有时，随伴拒收。

### 增量换装包（`outfit.json`）

只给已有宠物新增或更新单套服装时，投递文件夹内只放 `outfit.json`（不放 `pet.json`/`teaching.json`/`tool.json`）与对应图片文件（`outfits/<id>.webp` 或 `.png`，及可选的 `activities/...`）：

```json
{
  "petId": "lizi",
  "outfit": {
    "id": "pajamas",
    "displayName": "睡衣",
    "spritesheetPath": "outfits/pajamas.webp"
  },
  "scheduleRule": {
    "outfit": "pajamas",
    "when": { "time": { "from": "22:00", "to": "07:00" } }
  },
  "activities": []
}
```

- `scheduleRule` 与 `activities` 均为可选。若给出 `scheduleRule`，其 `outfit` 必须等于 `outfit.id`；更新已有服装时原地更新其对应排程规则，不产生重复规则。
- `outfit.sleepStrip` 可选，格式为 `outfits/<id>-sleep.png` 或 `.webp`（16 帧 `3072×208` 透明条图）。对已安装服装可仅传 `outfit.id` + `outfit.sleepStrip`（省略 `spritesheetPath`）执行睡觉动作增量补丁，原服装图集保持不动。
- 回执（`.done-<名字>.json`）格式：
  ```json
  { "kind": "outfit", "petId": "lizi", "outfitId": "pajamas", "displayName": "睡衣", "updated": false }
  ```

修改现有动作仍使用 `teaching.json`：`replaceActions` 列出要替换的动作编号，`baseVersion` 是取参考图时的已接受版本。修改包只包含这些动作，保留原帧数与节奏，不附带规则变更。宿主检查固定开放范围和参考版本，收到后先展示草稿。原图集、历史版本和规则保留。


## 随伴怎么回复

随伴每 2 秒看一次收件箱。

- **收下：** 写 `inbox/.done-<名字>.json`，再删掉送来的文件夹。回执内容举例：
  ```json
  { "kind": "pet", "petId": "lizi", "name": "栗子", "updated": false }
  { "kind": "teaching", "petId": "lizi", "draftId": "1793819129-28d9b8c4", "summary": "单击它就挥挥手" }
  ```
- **拒收：** 把文件夹改名为 `inbox/.failed-<名字>/`，在里面写 `error.txt`，内容是给人看的原因。

制作端读到回执后，删掉 `.done-` 文件。没人读的回执和拒收的文件夹，随伴会在一天后清掉。

## 制作端怎么用

两个 Skill 都带同一个 `scripts/deliver.py`，测试保证两份一样：

```python
from deliver import Refused, deliver
result = deliver(package_dir, ["pet.json", "spritesheet.webp"], "lizi", wait=8)
```

- 返回 `{"status": "received", ...回执}`：随伴已收下。
- 返回 `{"status": "queued"}`：随伴没在运行，包留在收件箱里，下次打开时处理。
- 抛出 `Refused`：随伴拒收，异常信息就是原因。

## 代码位置

- 随伴：`apps/desktop/src-tauri/src/inbox.rs`（读收件箱、分派、写回执），`main.rs`（收到后选中宠物、弹窗、通知界面）。
- 制作端：`skills/*/scripts/deliver.py`。
- 测试：`inbox.rs` 里的 Rust 测试，`tests/test_deliver.py`。

### 工具卡

投递文件夹使用 `tool-` 加 32 位十六进制随机编号。只收一个普通文件 `tool.json`（最多 2048 字节），里面只有清单编号 `id` 和一条 1–100 字的中文 `reason`。随伴按内置清单解释它，不从包里取程序、地址、权限或凭据。写入顺序同前。

收到后先写 `.done-<投递编号>.json`，状态为 `received`，并展示待确认卡。用户选择后另写 `.decision-<投递编号>.json`，状态为 `enabled` 或 `discarded`。两种回执都有 ticket 和 id，查询时优先读决定回执。未处理的草稿保存在随伴中；回执按一天期限清理，过期后以随伴设置页为准。

### 旧版动作

已接收的动作和历史画面按宠物、动作编号保存。`custom/action-library.json` 保存当前选择和收藏条目；图片按内容复用。切换动作只更新当前选择，不创建编号快照。首次使用时读取旧版记录和已有草稿，旧文件保留作迁移备份。

暂不使用草稿时保留其中的动作。选用保存的画面只更新对应动作，触发安排保持当前状态。删除时先检查是否正在使用；共用图片仍被其他条目使用时继续保留，闲置图片放入系统废纸篓。
