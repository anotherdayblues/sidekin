# 教宠物新本领

把用户想法做成动作和触发安排，送回随伴。用户试播、接受后，由随伴本地执行。

保持同一角色，动作自然，首尾衔接待机。画面不合格就重做。

所有路径相对本 Skill；`SKILL_DIR` 指本目录。脚本只需要 Python 和 Pillow。

```bash
TEACH="python3 $SKILL_DIR/scripts/teach.py"
```

## 先确认用对了 Skill

| 用户想要 | 用什么 |
| --- | --- |
| 给已有宠物加新动作，并定它双击时做、随机做或每天定时做 | 本 Skill 的新本领流程 |
| 重画一个学会的动作 | 本 Skill 的“修改现有动作”流程 |
| 只改学会的动作什么时候做，或随机频率、睡觉时间、目光跟随、大小 | 不用 Skill。都在随伴首页：动作右上角的设置键、宠物名字旁的“⋯” |
| 去掉某个学会的动作或规则；回到以前的版本 | 在随伴里去掉，或从“旧版动作”重新选用 |
| 做一只新宠物；改整体长相 | `$make-desktop-pet` |
| 给软件加新功能（说话气泡、聊天、翻译、天气、在桌面走动） | 不用 Skill。这是改软件，去项目里读 `docs/扩展开发.md` |

## 修改现有动作

用户说“修改这个动作”“把当前动作改成……”或复制的任务带动作编号时，读 [修改现有动作](references/edit-actions.md)，使用 `new --replace`。它导出当前已接受的动作供生图参考，保持编号、帧数、节奏和规则，交回待确认草稿。

只能重画学会的动作，做一次的和持续的都可以；持续的保留原来的循环段。基础动作（待机、左右跑、打招呼、跳跃、失落、等待、专心工作、观察）暂不开放重画，睡觉保持原样。修改流程仍由用户在随伴里接受或回退。

## 按结束方式选择动作

按用户说的结束方式选：做一次就是普通动作，持续到叫停用 `loopFrames`。旧动作沿用原设置。

## 什么时候做：只有三种

学会的动作只能双击时做、随机出现、每天定时（可只在工作日），可以同时选几种。基础动作有自己固定的时机，不能替换，也不能另行安排。用户说了别的时机（单击、拖动、闲置、每隔多久……），说明只支持这三种，建议最接近的一种。写法见[规则写法](references/rules.md)。

## 生图工具

- **在 Codex 里**：用 `$imagegen`。
- **在别的 AI 里**：先查清你自己怎么生图、用什么工具。本文和参考文件里的 `$imagegen` 都换成你的工具，其他规则不变。
- **生图必须能附参考图。** 新动作要照着现在的宠物画，只靠文字画不出同一只。做不到就不要开始，告诉用户缺什么。

## 决定留给用户

接受、放弃、去掉和回到旧版本，都由用户自己在随伴里点。

- 不要用 computer use、AppleScript、模拟点击或任何别的方式，去点随伴里的“接受，让它学会”“不要了”“去掉”“回到这一版”“全部关闭”“删除”。
- 不要改随伴数据目录里的文件来代替这些按钮。新本领只能用 `stage` 送进收件箱。
- 用户说“帮我接受”时，告诉用户在随伴的哪里点，并说明这一步要用户自己确认。

## 省着用上下文

- **到哪一步才读哪份参考。** 第 2 步读 [规则写法](references/rules.md)；第 4 步读 [新动作制作](references/actions.md)。`teaching-contract.json` 不用预先读，脚本报错时再查对应的上限。
- **宠物和已学会的东西只用 `$TEACH pets` 看。** 不要去翻随伴的数据目录。
- **脚本只运行，不读源码。** 要知道参数，运行 `$TEACH <命令> --help`。
- **要做两个以上新动作时，每个动作派一个子代理生成。** 子代理只回传“图片路径 + 一句检查结论”。主对话只看 `add-action` 生成的 `qa/<名字>.gif` 和 `qa/<名字>-sheet.png`。
- **检查结果看结论。** `add-action` 的输出先看 `notes`，`check` 的输出看最后一行。

## 1. 看清现在的宠物

```bash
$TEACH pets
```

它列出随伴里的宠物、已学会的动作和规则，以及还没确认的草稿。用户没说是哪只而且不止一只时，问一句。没有宠物时，引导用户先用 `$make-desktop-pet` 做一只。

## 2. 把一句话翻译成计划，先说给用户听

读 [规则写法](references/rules.md)，把用户的话翻译成：

- **需要的新动作**：每个动作一句英文逐帧描述，一般 6–10 帧。能用基础动作表达的，就不新做。基础动作有：待机 idle、打招呼 waving、跳跃 jumping、失落 failed、等待 waiting、专心工作 running、观察 review。
- **什么时候做**：双击时、随机出现、每天几点（可只在工作日），三种里选，可以多选。每条规则只播一个新学会的动作一次，没有概率和冷却。

动手前用一两句中文复述计划，例如：“我会做一个新动作：抱着枕头出来打个哈欠再回去，每天 23:00 做一次。”连贯的表演做成一个动作。意思明确就直接开始；含糊时用合理默认值，并在复述里说出来。

用户的需求做不到时，直接说明，并给出最接近的做法。目前做不到的有：说话气泡、系统通知、联网条件（天气等）、在屏幕上走来走去。

## 3. 新建教学文件夹

在用户的工作目录或一个临时目录里：

```bash
$TEACH new --pet <编号> --dir <文件夹> --summary "给用户看的一句话"
```

它会导出 `references/idle-2x.png`（待机帧）和 `references/identity.png`（各标准动作各一帧），两张图都是身份参考。

## 4. 生成每个新动作

读 [新动作制作](references/actions.md)。每个动作按这三步做：

```bash
$TEACH prompt --dir <文件夹> --name pillow-walk --label "抱着枕头走出来" --frames 8 \
  --motion "1: calm idle stand. 2-3: ... 8: calm idle stand." --props "a small white pillow held in both front paws"
```

1. 用 `$imagegen` 按输出的 `prompt_file` 生成，附上全部 `input_images`。一次只生成一个动作，一张横条图。
2. 处理成动作：
   ```bash
   $TEACH add-action --dir <文件夹> --name pillow-walk --label "抱着枕头走出来" --strip <生成的图>
   ```
3. **必须亲自看** `qa/<名字>.gif` 和 `qa/<名字>-sheet.png`。GIF 前后各有一帧待机，用来检查衔接。必须确认：是同一只宠物；动作和用户描述一致；没有跳帧、闪烁或大小突变；首尾能自然回到待机；没有残留背景色块或多余物体。不合格就改提示词重新生成。同一个问题出现两次，就换方法：减少帧数、简化道具或减小动作幅度。

脚本的 `notes` 提示“首尾帧和待机差别较大”时，一定要看 GIF 确认。

## 5. 写规则

```bash
$TEACH add-rule --dir <文件夹> --json '{"id":"night-pillow","label":"晚上抱枕头出来","when":{"type":"clock","at":"23:00"},"do":[{"play":"pillow-walk"}]}'
```

改已有规则：用同一个 `id` 再写一次。去掉已有的动作或规则：`$TEACH remove --dir <文件夹> --rule <id>` 或 `--action <名字>`。只改规则、不加动作时，跳过第 4 步。

## 6. 检查并送到随伴

```bash
$TEACH check --dir <文件夹>
$TEACH stage --dir <文件夹>
```

`check` 用中文列出改动；`stage` 再检查一遍，然后放进随伴的收件箱。随伴在运行时，几秒内会弹出主窗口。随伴拒收时，脚本会给出原因；修好后再送一次。

最后告诉用户三件事：

1. 在随伴主窗口的“新本领”里，可以单独播放每个新动作，也可以点 ▶ 在桌面上试。
2. 由用户自己点“接受”，点了才生效。接受之前，桌面上的宠物照常生活。
3. 不满意就说“重做”或具体哪里不对。接受后，在首页动作区“学会的”一栏点动作右上角的设置键，可以改双击、随机、定时，也能重画或删除；在“旧版动作”里能预览、重新选用或删除保存的动作。

用户说“重做”时，沿用同一个教学文件夹，只改有问题的那部分，然后重新 `stage`。随伴里旧的草稿可以点“暂不使用”，动作会留在“旧版动作”。
