# 制作独立桌宠

你负责把用户的想法变成一只好看、像、动作自然的宠物。随伴（Pet Studio）负责在桌面上运行它，不需要 Codex、ChatGPT 或 API key。

保持角色长相，动作自然，质量优先。

`SKILL_DIR` 指本目录，所有路径相对于它。Python 需要 Pillow。

## 先确认用对了 Skill

| 用户想要 | 用什么 |
| --- | --- |
| 做一只新宠物；改整体长相；某个标准动作做得不好要重做 | 本 Skill |
| 给已有宠物加新动作；设定它什么时候、被怎么碰时做什么；改掉学会的东西 | `$teach-desktop-pet` |
| 只调随机频率、睡觉时间、目光跟随、大小 | 不用 Skill。在随伴首页调 |
| 给软件加新功能（说话气泡、聊天、翻译、天气、在桌面走动） | 不用 Skill。这是改软件，去项目里读 `docs/扩展开发.md` |

## 安静学习实验

专心工作默认用小幅、安静但能看出学习的动作。加 `--work-row original` 可切回原版；完整开关和重做方法见 [安静学习实验](references/work-row-laptop.md)。

## 给新宠物搭配持续动作

新宠物需随包导入睡眠横条。默认十分钟没碰就睡，单击才醒。规格和导出命令见[验收与导出](references/export.md)。

## 生图工具

- **在 Codex 里**：照官方流程用 `$imagegen`，本文其余规则照做。跳过下方仅供其他 AI 使用的传图参考。
- **在别的 AI 里**：先查清你自己怎么生图、用什么工具。官方说明和参考文件里的 `$imagegen` 都换成你的工具，`~/.codex` 下的路径跳过，其他规则不变。开始生图前，读 [其他 AI 的生图规则](references/other-ai-image-inputs.md)：次数上限必守，传图只看所用平台。
- **生图必须能附参考图。** 13 张图都要照着同一个主形象画，只靠文字画不出同一只宠物。做不到就不要开始，告诉用户缺什么。

## 决定留给用户

宠物送进随伴之后，随伴里的操作都由用户自己做：打开“放到桌面”、删除伙伴、接受、去掉新本领或回到旧版本。

- 不要用 computer use、AppleScript、模拟点击或任何别的方式替用户操作随伴。
- 不要改随伴数据目录里的文件。宠物只能用 `export_pet.py export --deliver` 送进收件箱。

## 本 Skill 对官方流程的改动

冲突时以这里为准：

1. **调用脚本**：官方写 `"$PYTHON" "$SKILL_DIR/scripts/<工具>.py" ...` 的地方，一律改成 `python3 "$SKILL_DIR/scripts/hatch.py" <工具> ...`，参数不变。适配层让中立帧使用 idle 第 0 帧，并保持 15 个未使用格透明。
2. **准备**：用 `scripts/project.py prepare` 代替直接运行 `prepare_pet_run.py`。它会调用官方脚本，再建立确认记录。
3. **长相先让用户确认**：官方生成主形象后直接继续；这里必须先给用户看，用户认可后才生成动作。参考图明确时出一版即可，需要探索时给少量候选。
4. **记录每一步**：每个视觉任务通过检查后，运行 `project.py accept`，写下实际看到的内容。局部重做用 `project.py repair`。
5. **统一配准**：九行都通过后、拼图集前，运行 `scripts/register_states.py`。
6. **导出和交付**：跳过官方“复制到 `~/.codex/pets`”和清理步骤，改用 `export_pet.py export --deliver`。
7. **不上传**：不调用 ChatGPT Pets 的上传、创建、选择或删除接口。

## 提示词的约束

`--notes` 会原样出现在每一条提示词的身份描述里：

- **只写长相**：物种、体型比例、脸、眼睛、花纹、颜色、材质、道具和要避免的特征。例：“橘白短毛猫，正常猫科头身比例，奶油白口鼻和四爪，琥珀色眼睛，尾巴有三道深橘环纹，柔和立体插画质感，不做夸张大头。”
- **不写制作要求**：动作、帧数、方向、衔接、验收这类词不写。`prepare` 发现这类词会拒绝执行。
- **真实宠物的照片**：用 `--reference` 传入，并在 `--notes` 里写清最能认出它的特征，比如花纹位置、耳朵形状、眼睛颜色。
- **背景**：沿用官方的色键背景。去背景和去色边由脚本完成，不要让生图输出透明背景。

## 进度清单

开始时建立这个清单，一次只推进一步，让用户看得到：

1. 准备「名字」：名字、描述、参考图、风格、工作目录。
2. 想象「名字」的样子：生成主形象，**等用户确认**。
3. 画出「名字」的动作：九行标准动作，再做四个主方向和两行注视方向。
4. 孵化「名字」：拼装、检查、预览、导出并送进随伴。

## 开始与恢复

- **新建**：确定简短名称、长相描述和工作目录，运行 `project.py prepare`。
- **性格介绍**（`--description`）：写这只宠物的性格，一两句。用户说过性格就用用户的话；没说就按它的长相写，语气温和，不夸张。准备和导出用同一句。它会出现在随伴“性格”框的开头，聊天时宠物按它说话。
- **继续**：运行 `project.py status`，看 `ready` 里下一步做什么。沿用原来的 `pet_id` 和已确认的素材。
- **修复**：只对某个动作不满意时，`project.py repair --job <动作> --reason ...`，只重做这一行。要改整体长相时，回到主形象确认。

## 交付

`export_pet.py export --deliver` 导出后把宠物包送进随伴。按输出里的 `delivery` 告诉用户：

- `received`：宠物已经在随伴里，主窗口会弹出来。同一只宠物再次送达会更新原来那只。
- `queued`：随伴没在运行。宠物包在它的收件箱里，下次打开随伴就会出现。
- 脚本报“随伴拒收”：按给出的原因修好，重新导出并送一次。

最后告诉用户三件事：

1. 宠物包的位置（文件夹和 ZIP），可以分享或备份。
2. 在随伴里打开“放到桌面”开关，宠物就会出现在桌面上。
3. 以后想让它学新动作，或在某个时间、某种互动时做某件事，直接说出来，用 `$teach-desktop-pet`。
